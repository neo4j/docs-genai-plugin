= Generate structured output

The functions `ai.text.structuredCompletion` and `ai.text.aggregateStructuredCompletion` can be used to generate structured output based on a textual input prompt and an output schema, represented as a Cypher map.
It is similar to submitting a prompt to an LLM, but with the additional guarantee that the output conforms to the requested schema.


[role=label--new-2026.02]
== Generate structured output for a single value

.Signature for `ai.text.structuredCompletion`

[cols="1,1,1,3"]
|===
|    *Syntax*        3+| `ai.text.structuredCompletion(prompt, schema, provider, configuration = {}) :: MAP`
|    *Description*   3+| Generate structured output as a map based on the specified prompt and JSON schema.
.5+| *Inputs* | *Name*          | *Type*   | *Description*
| `prompt`        | `STRING` | The prompt to generate output from.
| `schema`        | `MAP`    | A map describing the JSON schema for the desired output.
| `provider`      | `STRING` | The identifier of the provider: 'Azure-OpenAI', 'Bedrock', 'OpenAI', 'VertexAI'.
| `configuration` | `MAP`    | Provider specific configuration, use `CALL ai.text.structuredCompletion.providers()` to find the configuration needed for each provider. You can specify additional vendor options by adding `vendorOptions` with a map of values that will be passed along in the request.
2+| *Returns*     | `MAP`    | A structured map conforming to the provided schema.

    token: $openaiToken,

MATCH (r:Review)

           type: 'object',
           properties: {
             painPoints: { type: 'array', items: { type: 'string' } },

             sentiment: { type: 'string', enum: ['negative','neutral','positive'] }
           },
           required: ['painPoints','requestedFeatures']

         'openai',

             sentiment: { type: 'string', enum: ['negative','neutral','positive'] }
           },
           required: ['painPoints','requestedFeatures']
         },
         'bedrock-nova',
         conf
       ) AS review_insights;
----

|===
| review_insights
| {painPoints: ["pricing confusion"], requestedFeatures: ["annual billing"], sentiment: "neutral"}
|===

Use grouping keys appropriately: everything not aggregated must be included in the `RETURN` grouping.

[[web-access]]
== Allow models to access the web

Some models visit URLs if prompted to do so, but not all do.
OpenAI requires the `tools` list to include `web_search`, provided via `vendorOptions`.

[source, cypher]
----
WITH
  {
    type: 'object',
    properties: {
      paragraph: {type: 'string'},
      sentence: {type: 'string'}
    },
    required: ['paragraph', 'sentence'],
    additionalProperties: false
  } AS schema
RETURN ai.text.structuredCompletion(
  'Summarize https://en.wikipedia.org/wiki/Neo4j',
  schema,
  'OpenAI',
  {
    token: $openaiToken,
    model: 'gpt-5-nano',
    vendorOptions: {
      tools: [{
        type: 'web_search'
      }]
    }
  }
)
----


[[schema-requirements]]
== Schema requirements

The `schema` argument is a Cypher map that must adhere to the JSON schema specifications of the chosen provider.
Although most providers support standard JSON schema types (`string`, `number`, `boolean`, `object`, `array`), there are important differences in strictness and supported keywords.

.Provider specifics
[cols="1,3"]
|===
| Provider | Schema guidelines

| **OpenAI** / **Azure-OpenAI**
a| Uses a strict subset of JSON Schema. See the https://platform.openai.com/docs/guides/structured-outputs#supported-schemas[OpenAI docs] for more info.

* All object properties must be listed as `required`.
* All objects must specify `additionalProperties: false`.
* Supported types include `string`, `number`, `boolean`, `integer`, `object`, `array`, `enum`, and `anyOf`.

| **Vertex AI**
a| Uses a subset of the OpenAPI 3.0 Schema Object. See the https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/rest/Shared.Types/Schema[VertexAI docs] for more info.

* Best suited for flat or moderately nested structures.
* Ensure you check for specific keyword support (e.g., `nullable`).

| **Bedrock**
a| Uses the Converse API's tool definition format.

* While more flexible, it is recommended to follow the OpenAPI 3.0 schema standard for maximum compatibility across different foundation models (e.g., Anthropic Claude vs. Amazon Nova).

|===

[NOTE]
====
If you provide a schema with unsupported keywords for a specific provider, the function will return an error from the provider's API. Always start with a simple schema and increase complexity incrementally.
====
