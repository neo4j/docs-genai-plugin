= Use secrets for provider credentials

Instead of passing an API key or token as a string in the `configuration` map (for example as a query parameter), you can store it in the Neo4j Secrets Manager and refer to it by name.
The GenAI plugin then reads the credential when the function or procedure runs, so it never appears in your queries, query logs, or client applications.

[NOTE]
====
Secret names require the Secrets Manager, which is available in Enterprise Edition.
If it is not available, a call that uses a secret name fails with `The secrets manager is not available.`
Calls that pass credentials directly (`token`, `apiKey`, `accessKeyId`, `secretAccessKey`) keep working in all editions.
====

[[secret-name-parameters]]
== Secret name parameters

Each credential parameter has a secret name counterpart.
Use one or the other, not both.

.Secret name parameters
[opts=header, cols="2,2,2,3"]
|===
| *Secret name parameter* | *Replaces* | *Secret type* | *Used by providers*
| `tokenSecretName`  | `token`                           | String | OpenAI, Azure OpenAI, Vertex AI
| `apiKeySecretName` | `apiKey`                          | String | Vertex AI
| `awsSecretName`    | `accessKeyId` and `secretAccessKey` | AWS    | Amazon Bedrock
|===

Every `ai.*` function and procedure that takes a `configuration` map accepts these parameters, including `ai.text.embed`, `ai.text.embedBatch`, `ai.file.embedBatch`, `ai.image.embed`, `ai.image.embedBatch`, `ai.text.completion`, `ai.text.chat`, `ai.text.structuredCompletion`, `ai.text.aggregateCompletion`, `ai.text.aggregateStructuredCompletion`, `ai.text.classify`, `ai.text.score`, `ai.text.predicate`, `ai.text.decide`, and `ai.text.tokenCount`.

[[examples]]
== Examples

.Example -- Embed a string using an OpenAI token stored as a secret
[source, cypher, test-skip]
----
RETURN ai.text.embed(
  'Hello World!',
  'openai',
  { tokenSecretName: 'openaiToken', model: 'text-embedding-3-small' }
) AS result
----

.Example -- Count tokens using Amazon Bedrock credentials stored as an AWS secret
[source, cypher, test-skip]
----
RETURN ai.text.tokenCount(
  'Hello World!',
  'bedrock',
  { awsSecretName: 'awsCreds', model: 'eu.amazon.nova-micro-v1:0', region: 'eu-north-1' }
) AS result
----

.Example -- Generate text using a Vertex AI API key stored as a secret
[source, cypher, test-skip]
----
RETURN ai.text.completion(
  'Hello!',
  'vertexai',
  { apiKeySecretName: 'vertexKey', model: 'gemini-2.5-flash', region: 'europe-west2', project: 'my-project' }
) AS result
----

[[privileges]]
== Required privileges

The secret is read with the privileges of the user running the query.
// TODO: Verify the `ACCESS SECRET` privilege syntax and description against the Operations Manual once it is updated.
The user must have the `ACCESS SECRET` privilege on the named secret, for example:

[source, cypher, test-skip]
----
GRANT ACCESS SECRET openaiToken ON DBMS TO embedders
----

A user without this privilege gets an access denied error, and no request is sent to the provider.
Having `ACCESS SECRET` on a different secret is not enough.

[[behavior]]
== Behavior and errors

* *Secret type* -- `tokenSecretName` and `apiKeySecretName` require a string secret, and `awsSecretName` requires an AWS secret.
Using a secret of the wrong type is an error.
* *Mutual exclusivity* -- Setting both a secret name and its literal credential (for example `token` and `tokenSecretName`) fails with `Only one of 'token' or 'tokenSecretName' is expected to have been set`.
* *Invalid credentials* -- A secret value that contains a control character, such as a trailing newline, is rejected because it cannot be sent as an HTTP header.
* *Missing secrets* -- A secret that does not exist, or whose external value cannot be found, results in an error.
* *No leaking* -- Secret values are never included in error messages.
* *Per-transaction lookup* -- When a function is evaluated for many rows, the secret is looked up once per transaction and reused.

[[discover]]
== Discover supported parameters

The `ai.*.providers()` procedures list the secret name parameters as optional configuration entries alongside the credential they replace.
The credential itself is then listed as optional, because you can supply either.

[source, cypher, test-skip]
----
CALL ai.text.embed.providers() YIELD name, optionalConfigType
----
